Deploy order

Deploy the new API and UI builds first.
Run 04, then 05, then 06 on each database. Schedule 05 in a maintenance window, because building clustered indexes locks each table while it runs.
Run Migrate-LegacyPasswords.ps1 -Database <db> -DryRun, then run it again without -DryRun.
Once every database reports "remaining legacy: 0", set AllowLegacyPasswords=false in the API Web.config.

P2 (after P1, same maintenance window is fine)

Deploy the API/UI build that contains SafeRollback in DALHelper\clsDAL.cs before 09.
Run 07, then 08, then 09 on each database. All three are safe to re-run.
  07 replaces 7 posting procedures only where the database has exactly the version it was written for
     (SHA-256 check); other versions are skipped with a message. On WSHINE_VIG001, 3 of the 7 differ.
  08 adds 3 date indexes for the stock reports (seconds per index) and fixes one ISNULL filter.
  09 adds SET NOCOUNT ON / SET XACT_ABORT ON to the procedures (about 1.5 minutes) and guarded
     transactions to the writer procedures the API calls without one.
Every procedure that 07/08/09 changes is saved first in dbo.DbaProcBackup.
10 is optional and changes nothing by default: run section 1 to check blocking; keep
READ_COMMITTED_SNAPSHOT off (see its header).

P3 (setup before P1, then ongoing)

Before P1, on production: Deploy\Capture-PerfBaseline.ps1 -Database <db>  (read-only, Query Store).
  Output goes to D:\ShineBaselines (outside the repo; it contains query text).
After each deploy, once a few days of normal load have run:
  Capture-PerfBaseline.ps1 -Database <db> -CompareWith <earlier baseline folder>
11 is read-only. It lists SELECT *, UNION without ALL and (MAX) columns with a suggested size.
  Fix these only when a procedure is changed for another reason. Before resizing a column,
  check its maximum length in every customer database and in the API/UI models.
12 changes nothing by default. Set @SwitchToFull = 1 only if the business needs point-in-time
  restore, and register the log backups straight away (otherwise the log file keeps growing):
  Deploy\Register-BackupTasks.ps1 -Database <db,...> -BackupDir <dir> -WhatIf, then again without -WhatIf
  (elevated PowerShell). Backups are taken by Deploy\Backup-ShineDatabase.ps1.
